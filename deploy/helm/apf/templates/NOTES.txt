OpenShell is deployed by its own chart. Register this release there once the
APF pod is Ready; the OpenShell gateway calls Describe on every registered
extension at startup and fails closed if one is unreachable. Add this to the
OpenShell chart values, replacing <gateway_id> with the OpenShell gateway ID
(its chart fullname by default) and mounting the CA that issued the APF
serving certificate at /etc/apf-ca/ca.crt through server.extraVolumes and
server.extraVolumeMounts. Sandbox admission registers as a gateway
interceptor{{ if $pg.openshell.egress.enabled }} and egress request policy as supervisor middleware{{ end }}:

gatewayConfig:
  openshell.gateway:
    provider_profile_sources:
      - type: interceptor
        name: apf/policy-adapter
  openshell.gateway.interceptors:
    - name: apf/policy-adapter
{{- if $pg.openshell.admission.allowInsecureTransport }}
      grpc_endpoint: http://{{ $host }}:{{ $pg.openshell.admission.port }}
      allow_insecure_transport: true
{{- else }}
      grpc_endpoint: https://{{ $host }}:{{ $pg.openshell.admission.port }}
      tls_ca_cert_path: /etc/apf-ca/ca.crt
{{- end }}
      audience: urn:openshell:extension:interceptor:<gateway_id>
      order: 0
      failure_policy: fail_closed
{{- if $pg.openshell.egress.enabled }}
  openshell.supervisor.middleware:
    - name: apf-content-policy
      grpc_endpoint: https://{{ $host }}:{{ $pg.openshell.egress.port }}
      audience: urn:openshell:extension:middleware:<gateway_id>
      tls_ca_cert_path: /etc/apf-ca/ca.crt
      max_payload_bytes: 4194304
      timeout: 10s
{{- end }}

Each listener's trust.toml must carry the same audience as its stanza above,
issuer openshell-gateway:<gateway_id>, and the kid and public.pem from the
OpenShell JWT Secret. The chart README covers the derivation.
